# تابع من هنا — حالة المشروع عند 1.13.3 (دليل تسليم للمطوّر التالي)

هذا الملف يكفي لشخص جديد (أو مساعد ذكاء اصطناعي جديد) كي يكمل العمل دون الرجوع إلى أي محادثة سابقة.
اقرأه كاملاً مرة واحدة (10 دقائق) ثم ابدأ من قسم «الخطوة التالية».

## 1. ما هو المشروع

- **restore-store**: قالب متجر إلكتروني موريتاني (عربي/فرنسي، MRU، واتساب، بنكيلي) + لوحة تحكم. بدون إطار عمل:
  HTML/CSS/JS خام، وحدات ES تحت `assets/js/`. قاعدة البيانات والتخزين: Supabase. الاستضافة: Cloudflare Pages.
- **القالب** في مستودع `AI-SAFWA/store-template`. كل متجر عميل هو مستودع منفصل (`AI-SAFWA/store-demo1` حالياً)،
  مسجّل في `clients.json`. عندما يُدفع tag جديد `vX.Y.Z` على القالب، يُحدِّث GitHub Action
  (`.github/workflows/release.yml`) كل متاجر العملاء تلقائياً، وCloudflare ينشرها.
- demo1 منشور على `store-demo1.pages.dev` (المتجر) و`/dashboard` (اللوحة). Supabase: مشروع باسم **Laptop**.

## 2. الهدف الجاري

تاجر غير تقني، يعمل من **الهاتف**، يجب أن يدير متجره بالكامل من اللوحة. لذلك نبسّط اللوحة **شاشةً شاشةً، كل شاشة في
إصدار**، ولا ننتقل إلى الشاشة التالية حتى يختبر المالك الإصدار على demo1 ويقول «تم».

مبادئ ثابتة اتُّفق عليها مع المالك:

- قبل أي تنفيذ: **صورة (mock) للشاشة** يوافق عليها المالك. ثم التنفيذ، ثم لقطات من الكود الفعلي.
- تصميم «خطوات مرقّمة» (بطاقات بيضاء، رقم برتقالي/أزرق)، زر حفظ ثابت أسفل الشاشة، العربية أولاً والفرنسية مطوية
  وتُنسخ من العربية إن تُركت فارغة. المصطلح الموحّد في الكود: صنف `.pe` / `.pe-step` (انظر `07b-product-editor.js`).
- **لا تغييرات في SQL ولا في بنية البيانات** داخل إصدارات الواجهة. معرّفات المنتجات القديمة (handles) لا تتغير.
- كل إصدار يُسلَّم كـ: `release-X.Y.Z.zip` (الملفات المتغيرة فقط) + `src-snapshot.zip` (الشجرة كاملة) + خطوات نشر مرقّمة.
- «تذكّرني على هذا الجهاز» يبقى **غير مفعّل افتراضياً** (قرار المالك).
- اللغة مع المالك: العربية، خطوات مرقّمة قصيرة، لا تُغرقه بالتفاصيل التقنية.

## 5. كيف تعمل على إصدار (الإجراء الحرفي)

```bash
npm ci                               # مرة واحدة
npx playwright install chromium      # للـ e2e
npm run check                        # يجب أن ينتهي بـ exit 0 (lint + typecheck + unit + smoke + db)
npx playwright test                  # 18 سيناريو، كلها يجب أن تنجح
```

قواعد الفحص التي ستصطدم بها:

- أقصى حجم للملف 600 سطر (`scripts/check-syntax.mjs`) → قسّم إلى ملف جديد `NNx-name.js` وسجّله في `assets/js/dashboard.js`
  (`import { install as sNNx }` ثم `sNNx(ctx)` بالترتيب).
- تعقيد الدالة ≤ 15 (ESLint) → استخرج دوالّ صغيرة.
- لا أنماط inline (`style="..."`) → استخدم `data-sv="bg:..."` (انظر `ui/style-vars.js`) أو أصنافاً.
- أيقونات اللوحة: `ctx.icon("name")` من `ui/dashboard/00-context.js`؛ أضف الاسم هناك إن لم يوجد.
- كل حقل تعديل في نافذة: `data-edit-path="a.b"` يكتب في `ctx.editBuffer` تلقائياً؛ الحفظ عبر `data-action="save-editor"`
  وخريطة `EDITOR_SAVERS` في `22c-actions-forms.js`.
- الأزرار: `data-action="..."` وتُسجَّل في `22*-actions-*.js`.

إغلاق الإصدار:

1. ارفع الرقم في `assets/js/version.js`، `package.json`، `package-lock.json` (موضعان)، وأضف مدخلاً في `CHANGELOG.md`.
2. إن غيّرت ملفات المتجر (لا اللوحة): ارفع `CACHE` في `sw.js`.
3. ابنِ `release-X.Y.Z.zip` من الملفات المتغيرة فقط، و`src-snapshot.zip` للشجرة كاملة بدون `node_modules`.
4. سلّم المالك: الصورة الحقيقية للشاشة + القائمة المرقّمة أدناه.

خطوات النشر التي يعرفها المالك (لا تغيّر صياغتها):

```
1. فكّ release-X.Y.Z.zip فوق مجلد القالب مع الاستبدال.
2. PowerShell داخل مجلد القالب:
   git add -A
   git commit -m "X.Y.Z"
   git push
   git tag vX.Y.Z
   git push --tags
3. انتظر Actions (القالب ثم store-demo1) حتى تخضرّ.
4. أغلق المتصفح وافتح store-demo1.pages.dev/dashboard → تأكد من vX.Y.Z أسفل القائمة.
```

## 7. أخطاء وقعنا فيها (لا تكرّرها)

- الجلسة: مفاتيح Supabase في الذاكرة فقط؛ بعد إعادة التحميل يلزم دخول جديد ما لم يُفعَّل «تذكّرني». فتح اللوحة في تبويبين كان يُبطل أحدهما (حُلّ بـ BroadcastChannel).
- `Ctrl+Shift+R` لا يكفي أحياناً؛ ملفات JS تُخدَم من Service Worker: أغلق المتصفح كلياً أو ألغِ تسجيل SW.
- `fetch("data:...")` ممنوع بالـ CSP داخل اللوحة.
- SVG بدون `width/height` في CSS يُرسم 300×150.
- عند تشغيل الاختبارات تحت Node، `BroadcastChannel` يُبقي العملية حيّة → `channel.unref()`.
- الشجرة المحلية انحرفت أكثر من مرة عن النسخة المنشورة؛ **ابدأ دائماً من `src-snapshot.zip` أو من tag المستودع**، لا من مجلد قديم.

## 8. ما يحتاجه الشخص الجديد من المالك

1. صلاحية **Write** على مستودعي `store-template` و`store-demo1` في GitHub.
2. دعوة إلى مشروع Supabase **Laptop** (دور Developer يكفي للـ SQL Editor).
3. (اختياري) وصول إلى Cloudflare Pages لمتابعة النشر.
4. حساب دخول إلى لوحة demo1 بدور مالك.
5. هذا الملف + `docs/HANDOVER.md` + `CHANGELOG.md`.
