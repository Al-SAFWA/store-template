# قائمة الإطلاق (Go-live) — متجر جديد لتاجر حقيقي

اتبع البنود بالترتيب. كل بند يُنجز مرة واحدة لكل متجر. ضع ✔ أمام ما أُنجز.

## 1) قبل التسليم (على حاسوبك)
- [ ] أنشئ المستودع من القالب وشغّل الأتمتة (انظر `docs/AUTOMATION.md`).
- [ ] مشروع Supabase جديد، ونفّذ `supabase/ALL_IN_ONE.sql` مرة واحدة.
- [ ] **متجر قائم قبل 1.17؟** نفّذ `supabase/migrations/0006_stock_bumps_catalog.sql` ثم `0007_security_hardening.sql` في SQL Editor (آمنان على البيانات الحية). بدون 0007 يستطيع المدير ترقية نفسه إلى مالك، ويستطيع الزبون إرسال خصم 100% من المتصفح.
- [ ] حساب المالك له صف في `restore_staff` بـ `active = true` (منذ 0007 لا يكفي دور JWT وحده).
- [ ] ضع `supabaseUrl` و`anon key` في `assets/js/config.js`. لا تضع أبداً `service_role`.
- [ ] `npm ci && npm run check && npm run test:e2e` كلها خضراء محلياً.
- [ ] ادفع الوسم `v1.0.0` وتأكد أن Actions أخضر وأن المتجر يفتح على الرابط.
- [ ] دالة `create-order` منشورة مع `ALLOWED_ORIGIN=https://الدومين` ، ويُفضَّل `TURNSTILE_SECRET_KEY` (كابتشا مجانية من Cloudflare) للحد من الطلبات الوهمية.

## 2) تنظيف بيانات العرض
- [ ] «بيانات متجري»: الاسم، الشعار، واتساب التاجر، الهاتف، العنوان، رابط الخريطة، أوقات العمل.
- [ ] «الدفع والتوصيل»: أرقام حسابات بنكيلي/مصرفي/سداد الحقيقية، أطفئ ما لا يستخدمه، أسعار المدن.
- [ ] «المنتجات»: احذف منتجات العرض (أو أطفئها) وأضف 3 منتجات حقيقية على الأقل بصور حقيقية.
- [ ] «الفئات»: أبقِ فئات التاجر فقط.
- [ ] «الكوبونات والعروض»: احذف `WELCOME10`/`NOUAKCHOTT5`، واكتب شريط الإعلان الحقيقي.
- [ ] «الصفحات»: من نحن، سياسة الإرجاع، تواصل معنا — بنص التاجر.
- [ ] «الإعدادات» ← SEO: العنوان والوصف والرابط الأساسي (الدومين النهائي).
- [ ] اضغط «نشر».
- [ ] ألغِ كل طلبات التجربة بـ SQL الإلغاء (لا الحذف) حتى تتزامن الأجهزة.

## 3) الحسابات
- [ ] أنشئ حساب **مالك** للتاجر ببريده وكلمة مرور قوية؛ فعّل «تذكرني» على هاتفه فقط إن طلب.
- [ ] احذف حسابات العرض (`owner@`/`manager@` التجريبية).
- [ ] إن كان له موظف: «الفريق» ← حساب **مدير** (لا يرى الفريق/الإعدادات/سجل النشاط).

## 4) اختبار على جهازين حقيقيين (هاتف التاجر + هاتفك)
- [ ] من هاتفك كزبون: تصفح ← منتج ← سلة ← دفع ← اختر بنكيلي ← يظهر رقم الحساب وزر نسخ ← أكمل ← تفتح واتساب على رقم التاجر بالرسالة الصحيحة.
- [ ] على هاتف التاجر: وصل الطلب في «نظرة عامة» و«الطلبات» مع صوت/تنبيه ← أكّد ← اشحن ← سلّم.
- [ ] من هاتفك: الطلب يظهر في «حسابي» بالحالة المحدّثة.
- [ ] اطلب إلى مدينة لها رسوم توصيل (مثل روصو 600): المجموع في لوحة التاجر يتضمن الرسوم (الخادم هو من يحسبها منذ 0007).
- [ ] التاجر يضيف منتجاً بصورة من كاميرا هاتفه ← ينشر ← يظهر في المتجر.
- [ ] غيّر سعراً ← انشر ← افتح المتجر في متصفح جديد: السعر الجديد ظاهر (لا كاش قديم).

## 5) النسخ الاحتياطي والاستعادة (إلزامي قبل التسليم)
- [ ] «الإعدادات» ← نسخة احتياطية ← صدّر الملف واحفظه خارج الهاتف (Drive/حاسوب).
- [ ] **جرّب الاستعادة** على متجر العرض: استورد الملف وتأكد أن المنتجات والإعدادات عادت. نسخة لم تُستعد مرة = غير موجودة.
- [ ] فعّل النسخ الدوري للمحتوى من الأتمتة (`automation/client/content-backup.yml`).
- [ ] في Supabase: Settings ← Database ← تأكد أن النسخ اليومي مفعّل (الخطة المجانية تحتفظ 7 أيام).

## 6) المراقبة بعد الإطلاق
- [ ] راقب صفحة Actions بعد كل إصدار (أحمر = لم يُنشر).
- [ ] عند شكوى "المتجر لا يعمل": افتح على هاتف الزبون «الإعدادات ← متقدم ← آخر الأخطاء» وأرسل صورة للمطوّر.
- [ ] Supabase ← Logs عند مشكلة في الطلبات أو تسجيل الدخول.

## 7) التراجع عن إصدار سيّئ (أمر واحد)
```
node scripts/rollback.mjs v1.16.0     # رقم آخر إصدار كان سليماً
git push && git push --tags
```
يعيد كل الملفات لذلك الإصدار وينشره كرقم جديد، دون المساس بقاعدة البيانات أو الطلبات.

## 8) اتفاق الدعم مع التاجر (اكتبه في رسالة واتساب مثبتة)
- من يدفع اشتراك Supabase/الدومين إن تجاوز المجاني.
- مدة الرد على الأعطال، وما الذي يفعله التاجر بنفسه (المنتجات، الطلبات، الكوبونات) وما الذي يطلبه منك (الألوان، الصفحات، الدومين).
- أين تُحفظ النسخة الاحتياطية ومن يملكها (التاجر دائماً).
